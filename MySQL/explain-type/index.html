对比：最容易混淆的几组

  
对比关键区别

    
const vs eq_ref都是主键/唯一索引等值查找、最多一行。const 是单表与常量比较，在优化阶段就能读出结果；eq_ref 出现在 JOIN 中，对前表的每一行最多匹配本表一行。

    
eq_ref vs refeq_ref 每次关联最多找到一行；ref 用普通（非唯一）索引或唯一索引的最左前缀做等值匹配，可能返回多行。

    
range vs indexrange 在索引中定位一个或多个区间再扫描；index 从头到尾扫描整个索引。

    
index vs ALLindex 扫描全部索引项，ALL 扫描全部数据行。覆盖索引时 index 通常读得更少，但并非所有数据分布下都必然更快。

    
type=index vs Extra: Using index前者是"全索引扫描"这一访问方式；后者表示用了覆盖索引、不必回表。两者可以同时出现，也可以单独出现（例如 ref + Using index）。

  

  

    其余 5 种 type（了解即可）
    
type含义与典型写法

      
fulltext使用 FULLTEXT 索引：MATCH(title) AGAINST('mysql')。

      
ref_or_null类似 ref，额外查找 NULL：WHERE age = 20 OR age IS NULL。

      
index_merge合并多个索引的结果，Extra 中会出现 Using union / intersect / sort_union：WHERE a = 1 OR b = 2（a、b 各有索引）。

      
unique_subqueryvalue IN (SELECT 主键 FROM t WHERE ...) 形式的子查询，用唯一索引查找。

      
index_subquery同上，但子查询使用非唯一索引。MySQL 8 中这两种子查询常被半连接等策略改写，较少见到。

    

    
官方完整顺序（从优到劣）：system → const → eq_ref → ref → fulltext → ref_or_null → index_merge → unique_subquery → index_subquery → range → index → ALL。

面试一句话总结

  
通常要求查询至少达到 range，等值查询争取 ref 或更好。但评估 SQL 时还要结合 key、key_len、rows、filtered、Extra，必要时用 EXPLAIN ANALYZE（MySQL 8.0.18+）查看实际执行情况。

  
示例表结构：users(id PRIMARY KEY, name VARCHAR(50), age INT, INDEX idx_age(age))；orders(id PRIMARY KEY, user_id BIGINT, INDEX idx_user_id(user_id))。users.name 没有索引。
