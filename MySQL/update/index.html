02 · 日志职责

Undo、Redo、Binlog 分别做什么？

Undo Log

InnoDB 层，保存修改前的数据，用于事务回滚，也支撑 MVCC 的旧版本读取。

回滚 / MVCC

Redo Log

InnoDB 层的物理日志，记录页的修改，保证崩溃恢复，让数据页可以延后刷盘。

持久性 / 崩溃恢复

Binlog

Server 层的逻辑日志，用于主从复制和基于时间点的恢复。

复制 / PITR
03 · 面试总结

40 秒回答模板

阶段对应步骤可以这样说
1. 定位记录①执行器调用 InnoDB，通过索引定位记录，数据页不在内存时从 .ibd 读到 Buffer Pool。
2. 修改前保护②先记录 Undo Log，用于回滚和 MVCC。
3. 改内存页③在 Buffer Pool 中修改数据页，页被标记为脏页。
4. 写 Redo④同时生成 Redo，写入 Redo Log Buffer。
5. 两阶段提交⑤ ⑥ ⑦Redo prepare 刷盘 → 写 binlog 并刷盘 → Redo commit，保证 Redo 和 Binlog 一致。
6. 后台刷脏⑧提交成功后，脏页由后台线程异步刷回 .ibd，不在提交路径上。
