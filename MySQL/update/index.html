01

关键时刻

WHERE

定位目标行

WHERE id = 1 先通过主键索引定位到唯一的记录，减少扫描范围，避免全表更新。

LOCK

行锁与修改

InnoDB 对命中的行加 X 锁，确保同一时间只有当前事务可以修改这一行。

WAL

日志与提交

Undo 记录旧值，Redo 记录恢复所需变更，Binlog 负责复制和恢复，事务最终 COMMIT。

02

面试追问

Q：UPDATE 一定先写到磁盘吗？

不一定。通常 InnoDB 先改 Buffer Pool，并写入 Redo 日志，再等后台刷盘；真正落盘和事务提交不是同一个动作。

Q：为什么要有 Undo 和 Redo 两类日志？

Undo 负责事务回滚和 MVCC，Redo 负责崩溃后的恢复。两者职责不同，不能互相替代。

Q：UPDATE 里 binlog 是什么时候写的？

通常在事务提交阶段由 Server 层将事务对应的 binlog 事件写入 binlog 文件，随后决定是否同步到磁盘，配置会影响 fsync 策略。

重点：WHERE 定位、行锁、Redo/Undo、Binlog 与事务 commit，构成一条 UPDATE 的核心执行链路。
