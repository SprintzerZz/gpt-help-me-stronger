01 / 先建立正确的层次关系

InnoDB 不等于 Buffer Pool + Log Buffer；它们只是内存结构中的两个重要组件。

InnoDB 存储引擎

内存结构

按页缓存数据和索引等
Log Buffer
暂存 Redo 日志记录

磁盘结构 + 后台线程
表空间、Redo Log 等

Buffer Pool 里缓存哪些页面？

聚簇索引页

非叶子页：主键 + 子页定位信息

叶子页：完整行记录（常称“数据页”）

二级索引页

非叶子页：索引键 + 子页定位信息

叶子页：索引列 + 主键值

其他缓存页 例如 Undo 页
💡 核心：Buffer Pool 缓存的是“页”，不是只缓存某一行。它本身也不是 B+ 树，而是内存缓存池。

存储完整行记录

聚簇索引的叶子页保存整行数据，所以在 InnoDB 的语境下，通常把它称为“数据页”。

示例表
CREATE TABLE users (
  id BIGINT PRIMARY KEY,
  name VARCHAR(50),
  age INT,
  INDEX idx_age (age)
);
记忆关键点

数据页不是“一张 16KB 的大表”。一张表通常有大量页；一个页包含多条记录和各种页管理信息。

🔍 纠正常见误区：“索引页 = 非叶子页，数据页 = 叶子页”只是一种过度简化。二级索引也有叶子页，而且聚簇索引的叶子数据页，在物理页类型上也属于 INDEX 页。

06 / 三题快速自测

点击选项可立即查看答案。

Q1：二级索引的叶子页默认也有 16KB 吗？

Q2：二级索引 idx_age 的叶子页一般保存什么？

Q3：Buffer Pool 本身是 B+ 树吗？

面试背诵版：InnoDB 的 Buffer Pool 以页为单位缓存数据和索引等内容，默认页大小 16KB。聚簇索引和二级索引都是 B+ 树：聚簇索引叶子页保存完整行记录，二级索引叶子页保存索引列与主键值，非叶子页主要负责导航。虽然存储内容不同，但它们通常采用相同的索引页物理结构。
