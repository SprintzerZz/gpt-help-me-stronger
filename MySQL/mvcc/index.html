④ Read View 可见性判断规则（访问某版本 trx_id 时）

判断条件 是否可见 原理解释
trx_id == creator_trx_id ✅ 可见 该版本正是当前事务自己修改的，当然对自己可见。
trx_id < min_trx_id ✅ 可见 生成 ReadView 时，该事务早已提交，其修改对当前快照可见。
trx_id >= max_trx_id ❌ 不可见 该事务是在生成 ReadView 之后才开启的，不可见，需沿 roll_pointer 继续回溯。
min_trx_id <= trx_id < max_trx_id 看 m_ids 若 trx_id 在 m_ids 中（创建快照时仍未提交）→ ❌ 不可见；不在 m_ids 中（已提交）→ ✅ 可见。
注意区分「快照读」与「当前读」： 以上流程仅适用于普通 SELECT（一致性非锁定读 / 快照读）。若是 UPDATE、DELETE、SELECT ... FOR UPDATE 或 LOCK IN SHARE MODE，则属于当前读，会直接读取最新已提交版本并加锁，不走旧 ReadView。

核心结论：RC 每次普通 SELECT 都会重新生成 ReadView；RR 仅在事务内第一次普通 SELECT 时生成 ReadView，后续复用。 因此本例中 RC 两次查询为 6000 → 7000，RR 两次查询为 6000 → 6000。
