④ 常见面试追问
为什么需要间隙锁、临键锁？
在可重复读隔离级别，锁定读等场景中需要防止并发事务向查询范围插入新的记录。通过锁住相关索引间隙，可以防止这类插入导致的幻读。注意：普通一致性快照读主要通过 MVCC 获得一致视图，不能把防幻读全部归功于间隙锁。
间隙锁之间会互斥吗？
通常不会。InnoDB 的间隙锁具有“纯抑制插入”的语义，不同事务可以持有同一间隙的间隙锁，即使一个为共享、另一个为排他；它们主要与插入意向锁冲突。不要把间隙锁理解成普通互斥锁。
临键锁为什么是 (10, 20]，不是 [10, 20)？
InnoDB 的 next-key lock 定义是某条索引记录上的记录锁，加上它前面的间隙。例如记录 20 的 next-key 范围为 (10,20]。最后一个索引值之后还可能存在延伸至 supremum 伪记录的间隙。
唯一索引等值查询一定只加记录锁吗？
若查询条件完整匹配唯一索引、目标记录存在，且是锁定读，通常只需锁对应索引记录；如果目标不存在，可能锁住其应插入位置的间隙。若唯一联合索引只使用部分列，则不能按完整唯一等值查询看待。
READ COMMITTED 隔离级别还会有间隙锁吗？
会，但范围更有限。在 MySQL InnoDB 的 READ COMMITTED 下，通常禁用一般索引搜索与扫描的间隙锁定，外键约束检查、重复键检查等场景仍会使用间隙锁。
普通 SELECT 会加这些锁吗？
一般不会。普通 SELECT 是一致性读，主要使用 MVCC；SELECT ... FOR UPDATE、FOR SHARE、UPDATE、DELETE 等才需要重点分析锁定读与加锁范围。


⑤ 30 秒面试回答
InnoDB 的行级锁是基于索引实现的，主要包括记录锁、间隙锁和临键锁。记录锁锁住一条已有索引记录；间隙锁锁住索引记录之间的间隙，阻止其他事务插入；临键锁是记录锁加前面的间隙锁，例如 (10,20]，既能阻止修改记录 20，也能阻止往 10 到 20 之间插入。可重复读隔离级别下，InnoDB 会通过临键锁等机制防止锁定读的幻读；唯一索引完整等值命中已存在记录时，通常可以缩小为记录锁。具体加锁范围取决于实际扫描路径。
