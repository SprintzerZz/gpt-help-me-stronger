③ 为什么没有索引时 COUNT(*) 要扫描表？

切换“有无二级索引”，观察 InnoDB 可能采用的扫描路径。此处模拟的是常见的优化器选择，不是执行真实 SQL。

CREATE INDEX idx_name ON t1(name);

扫描对象聚簇索引 / 表记录
遍历聚簇索引记录，逐行计数

注意：InnoDB 中“全表扫描”通常是遍历聚簇索引（如果没有显式主键，InnoDB 会选择合适的唯一键或生成隐藏行 ID），并不是完全没有任何内部索引。
添加二级索引后，COUNT(*) 可能扫描更窄的二级索引，但仍需要遍历可见的索引记录；不是读取一个预先存储的精确总行数。实际方案以 EXPLAIN 为准。

④ 面试时怎么回答？

“COUNT(*) 和 COUNT(1) 都统计满足条件的行数，不会因为某个字段为 NULL 就漏掉这行，MySQL 中通常性能差别可以忽略。COUNT(列名) 只统计该列非 NULL 的行。InnoDB 不保存事务可见的精确总行数，所以需要扫描记录；有合适的较小二级索引时，优化器可能选择扫描二级索引。实际开发推荐用 COUNT(*)，语义清晰。”

补充：如果 COUNT(id) 的 id 可为 NULL，它也会漏掉 NULL 行。本示例的 id 未声明主键或 NOT NULL，因此不能从字段名推断它永不为 NULL。COUNT(DISTINCT col) 则是另一个语义：统计非 NULL 的不同值数量。
