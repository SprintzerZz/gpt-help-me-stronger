MySQL 核心分为 Server 层和存储引擎层；若细分，可以单独划出连接层。binlog 是 Server 层的日志，而 redo log 和 undo log 属于 InnoDB。

02 · Buffer Pool 是 B+ 树吗？（可点击演示）

不是。 B+ 树是 InnoDB 的索引组织结构；Buffer Pool 是内存缓冲池，缓存 B+ 树节点对应的索引页及其他数据页。点击「查询」逐步观察哪些页命中缓存、哪些页需要从磁盘加载。

面试一句话： B+ 树决定「怎么查找」，Buffer Pool 决定「页是否能直接从内存读取」。不会为了查一条记录而先加载整棵 B+ 树。

演示以 MySQL 8.0 / InnoDB 的典型事务提交路径为例，突出日志归属与提交顺序；不等于完整源码级调用时序。

BEGIN;
UPDATE account SET balance = balance - 100 WHERE id = 1;
COMMIT;
InnoDB · redo log
存储引擎层 · 物理页变更的重做日志
尚未进入 prepare

用于崩溃恢复；典型路径中先进入 prepare，再进入 commit。

MySQL Server · binlog
Server 层 · 记录逻辑变更，用于复制与恢复
尚未提交到 binlog 文件

事务执行期间可以先在 binlog cache 暂存，提交时再写入 binlog 文件。

注：写入（write）和刷盘（fsync）不同；是否每次提交同步刷盘受 sync_binlog、innodb_flush_log_at_trx_commit 等配置影响。binlog 不是执行 UPDATE 时直接由 InnoDB 写的。

Binlog · Server 层

  • 性质：逻辑变更日志（支持 ROW / STATEMENT / MIXED 格式）
  • 作用：主从复制、基于时间点恢复（PITR）
  • 范围：MySQL Server 机制，可配合支持的存储引擎使用
  • 写入：事务执行中缓存，提交阶段写入 binlog 文件；fsync 策略由配置决定

Redo log · InnoDB 层

  • 性质：物理/页级重做日志
  • 作用：崩溃恢复，支撑 WAL
  • 范围：InnoDB 存储引擎内部
  • 写入：执行时产生 redo；提交协调涉及 prepare / commit；刷盘取决于策略

04 · 面试 30 秒回答模板

“MySQL 常见分为 Server 层和存储引擎层 两大部分。如果细分，可以把连接层单独列出来。Server 层负责连接、SQL 解析、优化和执行，也负责 binlog；InnoDB 引擎负责数据读写、事务、锁，以及 redo log 和 undo log。

在 InnoDB 事务提交时，为了协调 binlog 与 redo log，MySQL 使用内部两阶段提交：先将 redo 置于 prepare 阶段，再提交 binlog，最后让 redo 进入 commit 状态。这样可以让崩溃恢复时判断事务是否应该提交，避免两种日志不一致。”

05 · 面试官常见追问

Q1：Binlog 属于 InnoDB 吗？MyISAM 有 binlog 吗？

不属于。Binlog 是 MySQL Server 层的二进制日志功能，不是 InnoDB 专属。符合 binlog 记录条件的 MyISAM 操作也可以写入 binlog；但 MyISAM 不具有 InnoDB 的事务和 redo log 机制。

Q2：为什么有 redo log 还要 binlog？

因为职责不同：redo log 解决 InnoDB 崩溃恢复，binlog 主要服务于复制和逻辑恢复。redo log 不是完整的、长期的业务变更历史，不能直接替代 binlog 的复制/PITR 用途。

Q3：两阶段提交是“先写 redo 再写 binlog”这么简单吗？

不够准确。redo 在事务执行期间就会产生，提交协调的关键顺序是 redo prepare → binlog 提交 → redo commit。Binlog 提交又涉及缓存、write 和按策略 fsync。不要把产生日志、写内存、写文件和同步落盘混成一个动作。

Q4：宕机时 redo 已 prepare、binlog 已成功提交，怎么办？

恢复期间 InnoDB 可以依据对应事务的 binlog 事务完成情况决定提交或回滚已 prepare 的事务；这正是协调机制的核心。实际恢复还受日志完整性与持久化配置影响。

Q5：UPDATE 一定会马上把数据页写入磁盘吗？

不一定。InnoDB 通常先修改 Buffer Pool 中的数据页并产生 redo，脏页可以随后再刷盘。WAL 的意义就是不必为了每次事务提交都同步刷新全部数据页。
