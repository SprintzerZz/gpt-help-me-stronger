HTTP/1.1 与 HTTP/2

一句话理解：HTTP/1.1 在持久连接上主要按请求组织传输，浏览器常用多条连接并行加载资源；HTTP/2 把请求拆成帧，在一条 TCP 连接上交错传输多个流。

HTTP/2

单连接：多个 Stream 交错传输

多个请求各有独立的流（Stream），分成帧（Frame），帧可在同一连接中交错发送；接收方按 Stream ID 重组。

同一条 TCP 连接

Stream A / B / C 在逻辑上独立

关键：多路复用，不需要为每个并发请求单独占用一条 TCP 连接。

03 · Frame 与 Stream 到底是什么？

浏览器

一条 TCP 连接内的二进制帧

流 1 HEADERS流 3 HEADERS流 1 DATA
流 5 HEADERS流 3 DATA流 5 DATA

每个 Frame 带所属 Stream ID，接收端按 ID 重组。

服务器

Stream（流）：一次请求/响应交换的逻辑通道。Frame（帧）：HTTP/2 传输的基本单位，例如 HEADERS、DATA。Multiplexing（多路复用）：多个流的帧可交错共用同一条连接。

05 · 易错重点：HTTP/2 仍有 TCP 队头阻塞

HTTP 层的阻塞得到改善

流 A 响应较慢时，流 B、C 不必完全停止传输。

A：慢B：继续C：继续

底层仍共用 TCP 字节流

TCP 丢包时，后续到达的字节可能等待重传，多个 HTTP/2 流一起受到影响。

TCP 包 1 ✓TCP 包 2 丢失 ✕TCP 包 3 等待交付
面试常考：HTTP/2 解决了 HTTP 层因响应顺序引发的队头阻塞，没有解决 TCP 层的队头阻塞。HTTP/3 基于 QUIC（运行于 UDP 之上），通过独立的传输流缓解跨流丢包阻塞。

06 · 真实项目怎么理解？

例如 Java Spring Boot 后端提供商品详情页接口，浏览器并发请求 /product、/reviews、/recommendations。HTTP/2 可在同一条连接上并发传输多路响应，减少为并发请求维护多条连接的必要性。

HTTP/2 不代表接口业务执行必然更快。如果瓶颈是慢查询、Redis 延迟、线程池排队或服务端 CPU，多路复用不会自动消除这些问题。

07 · 面试时可以这样回答

面试官：HTTP/1.1 和 HTTP/2 主要有什么区别？

HTTP/1.1 可复用 TCP 持久连接，但请求和响应组织相对简单，浏览器通常使用多条连接并行加载资源。HTTP/2 引入二进制分帧、Stream 和 HPACK 头部压缩，实现一条 TCP 连接上多个请求与响应的多路复用，并改善了 HTTP 层的响应排队阻塞。但它仍基于 TCP，发生丢包时多个流仍可能受 TCP 队头阻塞影响；这是 HTTP/3 改用基于 QUIC 的 UDP 的重要原因之一。

知识点依据：RFC 9113（HTTP/2）、RFC 7541（HPACK）、RFC 9114（HTTP/3）。
