    Comparison Matrix · 实时高亮当前选中版本

    ⑤ HTTP/1.0 · 1.1 · 2 · 3 全维度对比速查

    对比维度 HTTP/1.0 (1996) HTTP/1.1 (1997/1999) HTTP/2 (2015) HTTP/3 (2022)
    标准 RFC RFC 1945 RFC 2068 / 2616 → 9112 RFC 7540 → 9113（HPACK 7541） RFC 9114、QUIC 9000、QPACK 9204
    传输层协议 TCP（短连接） TCP（默认持久连接） TCP + TLS（规范允许 h2c，浏览器必开 TLS） UDP + QUIC（内置 TLS 1.3）
    连接管理 每次请求新建 TCP，响应即断（keep-alive 非标准） 默认持久连接复用；浏览器常对同源开约 6 条并发连接 单域名单连接 + 多路复用（多个 Stream 交错） Connection ID（0~20 字节）标识连接，Wi-Fi ↔ 5G 可平滑迁移
    传输格式 纯文本 ASCII 纯文本 ASCII + chunked 分块传输 二进制分帧（HEADERS / DATA 等） QUIC 加密帧（载荷与绝大多数传输头均加密，防中间盒干扰）
    头部压缩 无（每次重复发送） 无（Cookie / UA 冗余大） HPACK（61 项静态表 + 动态表 + Huffman） QPACK（99 项静态表 + 独立控制流同步动态表，避免跨流乱序阻塞）
    队头阻塞 (HOL) 无连接复用，但频繁建连开销更大 应用层 HTTP HOL（单连接响应必须按 FIFO 顺序返回） 改善应用层跨流阻塞，仍存在 TCP 传输层 HOL 消除跨流队头阻塞（QUIC 各流独立保序，单流丢包不阻塞他流）
    建连握手 (HTTPS) 每请求 2~3 RTT（明文 TCP 1 RTT） TCP(1) + TLS 1.3(1) = 2 RTT（TLS 1.2 为 3 RTT） TCP(1) + TLS 1.3(1) = 2 RTT（ALPN 协商 h2） 首次 1 RTT，会话恢复可 0 RTT（仅限幂等安全请求）
    关键特性与补充 基础 GET/POST/HEAD、Expires 缓存 强制 Host（虚拟主机）、Range 断点续传、Cache-Control 流优先级、流量控制、Server Push（主流浏览器已移除，改用 103 Early Hints） 抗弱网丢包、0-RTT 建连、支持 Alt-Svc 发现与优雅降级到 HTTP/2
    工程实战与面试高频补充：
    • 为什么现实中 HTTP/1.1 没看起来那么慢？ 浏览器通常会为同一域名同时建立约 6 条并行 TCP 连接（早期前端还会用「域名分片」开更多连接），代价是消耗更多端口、内存与 TCP 慢启动开销；升级 HTTP/2 后应取消域名分片，让同源请求复用同一连接。
    • HTTP/2 Server Push 现状： 规范曾引入服务端推送，但因服务端难以准确判断浏览器缓存状态（易推送冗余资源），Chrome 等主流浏览器已移除支持，现代实践改用 103 Early Hints。
    • HTTP/3 部署与兼容： 部分企业防火墙会拦截或限速 UDP 443 端口。服务端通过响应头 Alt-Svc: h3=":443"（或 DNS HTTPS 记录）通告支持 HTTP/3，浏览器并发探测（Happy Eyeballs），若 UDP 不通自动回退到 HTTP/2。

    一句话记住演进主线：1.0 每次建连 → 1.1 长连接串行 → 2 二进制多路复用（解了 HTTP 跨流阻塞，卡在 TCP）→ 3 改用 UDP/QUIC（消除跨流队头阻塞 + 1/0-RTT + Connection ID 连接迁移）。 提示：支持键盘 Space 播放/暂停、← / → 切换关键节点。
